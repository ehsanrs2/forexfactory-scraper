# ForexFactory Calendar Scraper

[![🤗 Hugging Face Dataset](https://img.shields.io/badge/🤗%20Dataset-Forex_Factory_Calendar-yellow)](https://huggingface.co/datasets/Ehsanrs2/Forex_Factory_Calendar)

Fetch ForexFactory economic calendar data into a long-lived CSV cache, keep the cache idempotent, and validate the result without duplicating rows.

The project provides a reproducible workflow for collecting, normalizing, storing, and validating ForexFactory calendar events.

The project does not bypass Cloudflare, CAPTCHA, or other security verification mechanisms. It uses public calendar HTML, saved HTML files, and weekly export files when available.

## Dataset

The processed ForexFactory economic calendar dataset generated by this project is publicly available on Hugging Face:

🤗 **Dataset:**
https://huggingface.co/datasets/Ehsanrs2/Forex_Factory_Calendar

The dataset is generated using this scraper workflow and includes:

* normalized calendar events;
* validated historical records;
* duplicate-free cache output;
* canonical datetime and event fields.

It can be used for:

* economic event analysis;
* financial research;
* machine learning feature engineering;
* historical market studies.

## Quick Start

Run the historical cache update with the default HTML provider:

```bash
python -m src.forexfactory.main \
  --start 2025-04-07 \
  --end 2026-04-06 \
  --csv forex_factory_cache.csv \
  --tz Asia/Tehran \
  --details \
  --debug
```

Validate the cache:

```bash
python scripts/validate_cache.py \
  --csv forex_factory_cache.csv \
  --start 2025-04-07 \
  --end 2026-04-06
```

## What This Project Does

* Fetches ForexFactory calendar rows and stores them in a CSV cache.
* Preserves historical rows outside the requested range.
* Merges repeated runs without creating duplicates.
* Supports legacy cache rows and newer normalized provider schemas.
* Validates duplicates and missing fields using canonicalized datetime, currency, and event values.

## Design Goals

This project focuses on reliable and reproducible data collection:

* **Idempotent cache updates**
  Repeated executions do not create duplicate historical events.

* **Historical preservation**
  Existing cache data is preserved when updating new date ranges.

* **Schema normalization**
  Legacy and new provider schemas are converted into a consistent representation.

* **Validation before analysis**
  Generated data is checked for duplicates, missing fields, and invalid timestamps.

## Recommended Workflow

1. Create and activate a virtual environment.
2. Run the update command.
3. Run the validation command.
4. Use the generated CSV cache for analysis or dataset generation.

The cache is treated as a long-lived historical store.

`--start` and `--end` control the fetch/update range only. They do not delete older rows.

## Updating the Cache

Default provider:

* `forexfactory-html`: online HTML fetcher, preferred for historical ranges.

Useful options:

* `--start`, `--end`: inclusive date range in `YYYY-MM-DD`.
* `--csv`: output cache path. Default: `forex_factory_cache.csv`.
* `--tz`: timezone used when canonicalizing times. Default: `Asia/Tehran`.
* `--details`: accepted for compatibility.
* `--impact`: filter by impact values such as `high,medium`.
* `--keep-currencies`: keep only selected currencies such as `USD EUR GBP`.
* `--provider`: choose `forexfactory-html`, `saved-html`, or `forexfactory-export`.
* `--input`: saved HTML file for `saved-html`.
* `--export-format`: `json`, `csv`, `xml`, or `ics` for `forexfactory-export`.
* `--debug`: write debug artifacts when HTML parsing detects blocked or malformed pages.

Example:

```bash
python -m src.forexfactory.main \
  --start 2025-04-07 \
  --end 2026-04-06 \
  --csv forex_factory_cache.csv \
  --tz Asia/Tehran \
  --details
```

## Validating the Cache

`scripts/validate_cache.py` canonicalizes legacy rows and normalized rows before checking duplicates, missing fields, and range coverage.

Example:

```bash
python scripts/validate_cache.py \
  --csv forex_factory_cache.csv \
  --start 2025-04-07 \
  --end 2026-04-06
```

Validation report fields:

* `total rows`: rows in the cache after canonicalization.
* `valid datetime rows`: rows with a canonical `datetime_local`.
* `range rows`: rows inside the requested validation range.
* `range duplicate groups`: canonical duplicate keys.
* `range duplicated rows including first`: duplicate rows counted across groups.
* `source counts`: rows written by each provider.
* `rows with missing source`: rows without source metadata.
* `legacy rows inside requested range`: rows using the legacy schema.
* `rows with missing key fields`: rows missing canonical datetime, currency, or event.

Current validated cache snapshot:

```text
range: 2025-04-07 to 2026-04-06

range rows: 4811
range duplicate groups: 0
range duplicated rows including first: 0
rows with missing key fields: 0
source forexfactory-html: 4802
source missing/legacy: 9
```

Small numbers of missing-source rows can be legacy cache rows and are not automatically errors if they do not duplicate canonical events.

## Understanding the Cache

* The cache is historical and cumulative.
* Re-running the same provider and date range should be idempotent.
* Duplicate detection uses canonicalized fields.
* Validation normalizes both legacy and new schema rows before checking.
* Older cache entries may not contain source metadata.

## Providers

### `forexfactory-html`

Default provider and preferred online method.

It fetches ForexFactory calendar HTML directly and parses calendar rows without Selenium.

### `saved-html`

Offline fallback for a local HTML file saved manually from a valid ForexFactory calendar page.

Example:

```bash
python -m src.forexfactory.main \
  --provider saved-html \
  --input saved_forexfactory_calendar.html \
  --csv forex_factory_cache.csv \
  --tz Asia/Tehran \
  --debug
```

### `forexfactory-export`

Optional export-file provider.

It discovers weekly export links when available and fetches:

* JSON
* CSV
* XML
* ICS

Important:

* It is not a public API.
* It depends on files exposed by ForexFactory.
* Historical coverage is not guaranteed.
* Export files may only contain recent calendar data.

Example:

```bash
python -m src.forexfactory.main \
  --provider forexfactory-export \
  --start 2025-04-07 \
  --end 2025-04-14 \
  --csv forex_factory_cache_test.csv \
  --tz Asia/Tehran \
  --export-format json \
  --debug
```

## Troubleshooting

### Direct HTML returns a security verification page

ForexFactory may return a page that contains security verification instead of calendar data.

The scraper reports this condition clearly.

It does not bypass verification systems.

### Parser cannot find calendar rows

If the HTML is valid but parsing fails:

* inspect saved debug HTML files;
* check whether ForexFactory changed the page structure;
* update selectors in the HTML provider.

### Empty CSV output

Possible reasons:

* no events exist in the selected range;
* the response was blocked;
* parser selectors need updating.

### Duplicate validation reports rows

Validate using the canonical duplicate key:

```text
datetime_local + currency + event
```

Inspect duplicate samples from the validation report.

### Missing source rows

Usually caused by older cache versions.

They are only problematic if they duplicate canonical events or miss required fields.

### Export historical limitation

If export files only expose current-week data, use `forexfactory-html` for historical ranges.

### Network or timeout failures

Retry later or use `--debug` to inspect fetched HTML and determine whether the response was blocked or malformed.
